# H4: preserve non-bat runs on no-ball deliveries

## A. Root cause

`Delivery.finish()` in `src/cricket.ts` calculated non-bat extras only when
`contact === 'miss' && !wide && !this.noBall`. It separately set `batRuns` to
zero for a miss. Thus a no-ball with genuine completed runs retained its
`completedRuns` and automatic penalty, but lost its byes or eligible leg-byes
when constructing the authoritative `DeliveryOutcome`.

The information was lost before `applyDelivery`, scorecard rendering or
serialization. Those consumers already accept the separate extras fields.
Reconstructing a delivery through the old finalizer reproduced the same loss.

## B. Existing scoring invariants

- The seeded constructor calls a no-ball when effort is at least `.92` and
  its existing random draw passes. The finalizer records `Number(this.noBall)`:
  one automatic penalty, independent of running. Detection is unchanged.
- A no-ball overrides a wide. Bat contact retains the supplied batter score;
  a miss receives zero batter runs.
- `advanceRunners()` alone completes a run when both batters ground at their
  destination creases. Partial attempts and the no-ball penalty never increase
  that count. Existing assisted/manual tolerances and tick ordering are unchanged.
- `judgeExtras()` classifies missed-ball runs as byes without pad contact, or
  as leg-byes with eligible pad contact. The current delivery model passes
  `shotOffered` as both the stroke and avoiding flags. Pad contact without an
  offered stroke remains ineligible; this task does not expand those rules.
- `Delivery.finish()` also sends untouched boundary runs to `judgeExtras`.
  The same gate correction applies to this existing branch.
- Production overthrows retain their separate optional `overthrowRuns: 1`
  field on eligible `fielded` outcomes. They are neither batter runs nor byes
  nor `innings.extras.penalty`. General `penalty` runs are supported by the
  reducer but are not generated by the current delivery simulation.
- Team runs and partnership runs add `batRuns + wide + noBall + byes +
  legByes + overthrowRuns + penalty`. Scorecard delivery/over totals use the
  same components. Bowler concessions add `batRuns + wide + noBall +
  overthrowRuns`, excluding byes, leg-byes and general penalties.
- No-ball deliveries increment attempts, preserve the legal-ball count and
  set free hit. They do not increment batter balls or bowler balls.
- Finalization preserves run-outs while suppressing other generated
  dismissals on a no-ball. The reducer retains its existing dismissal table.
  Completed-run parity, crossing and dismissed-batter identity place the
  survivors/replacement; none of these rules changed.
- The authoritative delivery outcome carries the scoring decision to the
  existing reducer. Local lifecycle guards skip scoring during replay and
  stop processing after settlement. Online settlement clears the active ball;
  accepted command sequences and replay cursors prevent duplicate inputs.
  `applyDelivery` is a reducer without delivery identity, not an independently
  idempotent event store: callers must not apply one event twice.

## C. Implementation

Removed only `&& !this.noBall` from the extras gate and added a comment
explaining that the automatic penalty is separate. The wide guard and
`judgeExtras` eligibility remain intact. This preserves genuine non-bat runs
without reclassifying batter runs or fabricating unfinished runs.

No reducer, scorecard, replay or network schema changes are needed. Their
existing fields now receive the complete outcome. The no-ball penalty is
still written once, and no new scoring call is introduced. H1 reconstruction,
H2 match-scoped review state and H3 grounding mechanics are unchanged.

## H. Limits and compatibility

- The production change applies to the existing untouched-boundary extras
  branch, but the new deterministic fixtures do not cover a non-bat boundary.
  No new boundary or additional extras category was introduced.
- General penalties remain reducer-supported; no artificial delivery fixture
  was used to imply the simulation generates them. Existing penalty tests cover
  that reducer behavior. Overthrows retain their existing separate bookkeeping
  and current `fielded`-outcome restriction.
- Historical sealed scores/checksums are not rewritten. Reconstructing an
  affected pre-fix delivery using corrected code can differ from its saved
  incorrect outcome; the existing replay format is unchanged.
- Duplicate protection is at the production lifecycle/command level. Directly
  invoking `applyDelivery` twice for the same event is still caller misuse.
- The compact no-ball token/call retains its existing shorthand. The full
  scorecard and authoritative totals receive the complete corrected extras.
- Pad avoidance semantics, wide-run behavior, unrelated boundary accounting
  and dismissal rules were inspected and left within their existing model.
